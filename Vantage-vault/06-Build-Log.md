## Progress log (newest first)
### 2026-05-29
- ✅ **Persona logins + real role switch + reasoning-in-trace + UI bug fixes (PR #23).** Five things that tangled together while polishing the demo UX. (a) Keycloak users renamed to the personas the vault stories already use — `priya.nair` / `priya` (sales), `marcus.webb` / `marcus` (support), `dana.okafor` / `dana` (admin); UI derives display name + initials from the dot-separated username (`marcus.webb` → "Marcus Webb", "MW"). (b) The role-switcher menu used to flip a frontend `this.role` variable — the JWT, Redis session, and realm roles never changed (server-side RBAC was correct, so it was safe; UX was misleading). Rewired: clicking a role hits `GET /auth/switch?username=<persona>` → clears the BFF session + revokes the Keycloak refresh token + drops the cookie → 302 to `/auth/login?prompt=login&login_hint=<persona>` → Keycloak forces re-auth → fresh JWT with the new realm roles. **One click = one real identity swap.** (c) Each assistant message now has a `timeline` interleaving the model's pre-tool narration ("thought" blocks) with tool-call pills; the frontend buffers text deltas and on `tool_start` commits the buffer as a thought + retracts the matching tail from `ass.md`, so only the *final-iteration* text remains as the answer. System prompt nudges the model to write 1–2 sentence intent narration before each tool call. (d) "Answer disappears, comes back when you switch chats" bug fixed — `loadSessions()` was wholesale-replacing `this.chats` with fresh objects (`messages: []`, `loaded: false`) when a new chat completed, wiping the just-streamed assistant turn from memory; now MERGES by id. (e) No emojis from the LLM — system prompt forbids them, defensive `EMOJI_RE` strip in `renderMd()` as belt-and-braces. Verified via the 75-test Playwright UI suite (`tests/ui/test_ui.py`, 14 categories) — **all 75 green** end-to-end against the Codespace stack.
- ✅ **Real SSE streaming via `/ask/stream` (PR #22).** Token-level streaming for the UI. Event types: `session` (UI adopts the server's session id before any content arrives), `text` (delta), `tool_start` (`{tool, input}`), `tool_end` (`{tool, status, ms}`), `done` (`{trace, elapsed_ms}`), `error`. Same agent loop as `/ask`; the OpenAI SDK's `stream=True` is wrapped to accumulate tool_call deltas across chunks. The non-streaming `/ask` stays for the eval harness (deterministic for assertions); `/ask/stream` is the UI surface. Persistence runs in `finally:` so partial answers from interrupted streams are still saved.
- ✅ **Browse tools (PR #21).** `list_customers` / `list_issues` / `list_next_actions` — filterable + paginated reads behind the MCP server. Mirrors the realistic v1 expansion: a user can ask "who are our customers?", "show me critical issues this week", "what's overdue?" without naming a specific id. The agent picks them when the user wants to browse, picks the targeted tools otherwise. Filters: customer name, region, tier, category, priority, status, date ranges; cursor pagination. RBAC at the tool boundary as ever.
- ✅ **UI wired to real backend (PR #20).** Frontend now talks to real `/ask/stream` + `/sessions` + `/skills/*` — no more mocked `routeQuery()` router. Sidebar chat history, save-as-skill modal, skill runner, multi-turn — all real. Skills authored from a session show up in the menu instantly.
- ✅ **OIDC Auth-Code + PKCE + BFF cookie (PR #18).** The chat UI's auth got upgraded from "dev ROPC tokens in the browser" to real production auth: `/auth/login` redirects to Keycloak with PKCE; `/auth/callback` exchanges the code server-side; tokens never reach the browser. The httpOnly `vantage_sid` cookie names a Redis-backed `auth_session:{sid}` (stored as access+refresh tokens + verified identity). `/auth/whoami` is the UI's bootstrap call. `/auth/logout` clears both ends and best-effort revokes the Keycloak refresh token. Cookie attributes (`secure`, `samesite`) configurable for the Codespaces HTTPS forward.
